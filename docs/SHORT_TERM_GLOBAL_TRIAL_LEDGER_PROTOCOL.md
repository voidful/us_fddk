凍結日期：2026-08-10

狀態：**在任何新披露策略結果及正式個股回測前，經獨立審閱補記第 24–28 輪已查看的
hypothesis family；只修正統計治理，不產生策略回報。**

## 目的

第十八輪一次性正式回測協議在 2026-08-04 凍結時，正確記錄當時全專案
`global_search_trials=6,208`。其後研究繼續增加已查看的績效路徑，但正式 readiness 程式仍把
6,208 當作永遠不變的值。若日後以較小次數計算 DSR 或 Bonferroni，會低估資料探勘風險。

本協議不覆寫第十八輪歷史收據。它建立一條只可追加的 **保守下限**，正式運行時必須使用：

```text
max(原始事前登記 6,208, 不可回減帳本目前下限)
```

帳本下限不是聲稱已精確枚舉每一次人手觀察；任何未能證明完整的家族只可令下限提高，
不能令次數減少或改稱「精確」。

## 每列固定欄位及雜湊鏈

機器帳本每列必須精確保存：

- 單調 `sequence`、唯一 `family_id`；
- `result_state`、`publication_state` 及是否已查看結果；
- `previous_lower_bound`、非負 `minimum_increment`、`current_lower_bound`；
- 來源檔 SHA-256；已提交來源另保存 repository 相對路徑並即時對數；
- `previous_entry_sha256` 及 canonical JSON `entry_sha256`。

Genesis 使用 64 個 `0`。Canonical 格式固定為 UTF-8、keys 排序、無空白分隔及禁止 NaN。
任一刪列、改次序、重用 family ID、負增量、算術不符、來源 hash 漂移、鏈頭不符或把
`seen_result=true` 改回 false，一律 fail closed。

本 v1.0 協議在第 41 輪 v1.1 收據及帳本鏈完成後永久不可原位編輯。日後找到遺漏 family
或需澄清計數語義，只可新增帶新路徑的 versioned amendment、append 新 ledger row 並更新
正式 policy binding；不得改這個檔案令歷史候選收據及 source hash 失效。

## 正式回測整合

- 第十八輪原收據必須仍精確等於 6,208；改動它視為歷史完整性失敗。
- 正式政策、run ID、DSR 及 Bonferroni 必須另綁定本帳本及本協議 SHA-256，並採用目前
  下限 6,287。run ID 只可使用已審計帳本的 digest，不可在 audit 後再讀檔形成 TOCTOU。
- 任何後續已查看或事前預留的績效 family，必須先追加帳本再准正式 readiness。
- 若帳本缺失、下限倒退、來源無法驗證或精確次數仍有爭議，只能提高懲罰或停止；不得回到
  6,208、重設為 1，亦不得因候選結果好看而改用較小 family。

這項修正不改第十八輪的訊號、研究期、成本、baseline 或經濟門檻，亦不授權正式策略運行。
目前合資格 provider package 仍為 0，正式策略結果仍為 0。

## 固定攻擊

驗證至少拒收：刪除中間列、次序不連續、family ID 重複、前值不等於上列、負增量、累計
算術錯、原始錨點不是 6,208、已見結果倒退、未發佈列冒充精確、已提交來源 hash 漂移、
鏈 hash 漂移、鏈頭不是凍結值、目前下限低於 6,287，以及正式 policy 仍使用 6,208／6,248。
